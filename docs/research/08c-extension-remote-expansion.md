# Extension, remote, and cloud-agent expansion

Checked: 2026-08-23

This is a primary-source expansion of three comparison tabs that were too narrow: IDE extensions, remote companions and relays, and cloud/background agents. It deliberately records exact SKUs. A vendor name is not a product: GitHub Copilot for IDEs, GitHub Copilot CLI, and GitHub Copilot coding agent are three different products with different execution boundaries.

## Recommendation

Add 10 IDE/plugin products, 8 remote/relay products, and 10 cloud/background products. Retain the existing products named below so their positioning can be corrected at the same time. Do not treat generic remote terminals as agent-aware approval clients, and do not treat PR-review bots as full coding agents.

Claim-state legend:

- `BI`: built in and directly documented
- `LIM`: present, but narrower than the row label
- `UNK`: not established by the cited primary source
- `NA`: the row does not apply to this product class

The ledgers use the current row IDs:

- Extensions: `extension-hosts`, `extension-inline-completion`, `extension-agent-panel`, `extension-background-delegation`
- Remote: `remote-client-reach`, `remote-existing-session`, `remote-approvals`, `remote-encryption`
- Cloud: `cloud-repo-intake`, `cloud-sandbox`, `cloud-live-observability`, `cloud-durable-result`

### Extension rows to add

1. `extension-install-channel`: VS Code Marketplace, Open VSX/VSIX, JetBrains Marketplace, Neovim plugin manager, bundled.
2. `extension-tool-execution-boundary`: host IDE, local sidecar/CLI, remote vendor agent, self-hosted server.
3. `extension-byok-local-model`: vendor-only, BYOK, OpenAI-compatible endpoint, local model, self-hosted inference.
4. `extension-agent-permissions`: approval prompts, auto-approve scope, diff review, rollback/checkpoints.
5. `extension-remote-session-client`: whether the extension can create, monitor, or resume a separately owned cloud/background session.

These rows prevent “has an agent panel” from implying autonomous background execution.

### Remote rows to add

1. `remote-agent-aware`: understands agent sessions, permissions, tool calls, or state versus streaming a generic terminal/editor.
2. `remote-input-model`: view only, raw terminal input, normalized follow-up messages, structured approve/deny, full workspace edit.
3. `remote-host-ownership`: existing local session, newly launched local session, remote SSH workspace, vendor cloud job.
4. `remote-client-surfaces`: browser, iOS, Android, desktop IDE.
5. `remote-relay-deployment`: direct/LAN, hosted relay, self-hostable relay, SSH/VPN supplied by user.
6. `remote-transport-security`: TLS/SSH transport, E2EE, zero-knowledge relay, deployment-dependent, unverified.
7. `remote-session-durability`: survives browser close, host UI exit, network loss, host sleep, or host process exit.

The current `remote-encryption` row should be renamed `End-to-end encryption documented`. SSH, HTTPS, Tailscale, and E2EE are materially different and must not all render as “Supported.”

8. `cloud-result-type`: patch, branch, PR/MR, review comments, deployment, workspace snapshot.
9. `cloud-network-policy`: none, allowlist, full egress, private connectivity, operator-controlled.

## Visibility correction for GitHub Copilot

The site should expose three separate columns in three tabs:

1. **GitHub Copilot for IDEs** — `ide-extensions`; runs as an IDE extension/plugin and provides completion/chat/agent surfaces.
2. **GitHub Copilot CLI** — `coding-agent-harnesses`; owns a terminal conversation and tool loop.
3. **GitHub Copilot coding agent** — `cloud-agents`; GitHub-hosted delegated work that produces a pull request.

Use the same vendor logo if necessary, but always show the exact SKU under it. Search aliases can include “Copilot,” while category routes and names keep the products distinct.
